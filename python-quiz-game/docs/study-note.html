Part 01

프로젝트 한눈에

누가 "이 프로그램이 뭐하는 거야?"라고 물었을 때 30초 안에 할 수 있는 대답.

터미널에서 실행되는 퀴즈 게임입니다. 메뉴에서 번호를 골라 퀴즈를 풀고 · 추가하고 · 목록을 보고 · 삭제하고 · 점수를 확인합니다. 프로그램을 껐다 켜도 추가한 퀴즈와 최고 점수가 그대로 남아있는데, 그 이유는 state.json이라는 파일에 매번 상태를 저장하기 때문입니다.

주제는 IT/컴퓨터 상식으로 정했습니다. 파이썬 문법을 익히는 김에 앞으로 계속 마주칠 개념(HTTP 상태 코드, CPU, 비트/바이트, RDBMS, Git 명령어, 운영체제)을 퀴즈로 복습하면 일석이조라고 생각했기 때문입니다 — 이 부분이 README의 "주제 선정 이유"입니다.

Part 02

Python 기초 — 실제 코드에서 찾아보기

문법을 안다는 것과, 그 문법이 실제로 왜 이 자리에 쓰였는지 아는 것은 다릅니다.

변수와 자료형 int · str · bool · list · dict

quiz_game.py의 _get_int_input 안에서 네 가지 자료형이 한 번에 등장합니다.

quiz_game.py
text = raw.strip()                 # str — 입력값에서 앞뒤 공백 제거
if not text.lstrip("-").isdigit(): # bool — 숫자로 바꿀 수 있는지 판정
    ...
value = int(text)                  # int — 실제 비교/계산에 쓸 정수로 변환

self.quizzes는 list(퀴즈 여러 개를 순서대로 담는 상자), self.best_score는 dict ({"score": .., "correct": .., "total": ..}처럼 이름표를 붙여 여러 값을 묶어두는 상자)입니다. 변수를 쓰는 이유는 이 값들이 프로그램이 실행되는 동안 계속 바뀌기 때문입니다 — 퀴즈를 추가하면 quizzes 리스트 길이가 늘고, 점수를 갱신하면 best_score 딕셔너리 내용이 바뀝니다.

조건문 if / elif / else

메뉴 선택에 따라 다른 동작을 골라야 하니 조건문이 필요합니다.

quiz_game.py — run()
if choice == 1:
    self.play_quiz()
elif choice == 2:
    self.add_quiz()
elif choice == 6:
    self.save_state()
    break

반복문 for vs while

이 프로젝트는 두 반복문을 용도로 구분해서 씁니다.

  • for — 정해진 개수를 돌 때. 예: 뽑힌 문제 목록(quizzes_to_play)을 처음부터 끝까지 출제할 때.
  • while True — 언제 끝날지 정해져 있지 않을 때. 예: 메뉴 입력을 "올바른 값이 들어올 때까지" 계속 다시 묻는 _get_int_input, 그리고 사용자가 5(현재는 6)번을 눌러 종료를 선택할 때까지 도는 게임 메인 루프.
quiz_game.py
for index, quiz in enumerate(quizzes_to_play, start=1):  # 개수가 정해져 있음
    ...

while True:  # 정답을 맞게 입력할 때까지 반복 (몇 번 걸릴지 모름)
    raw = input(prompt)
    ...

함수 매개변수 · 반환값

_get_int_input(prompt, min_value, max_value)가 좋은 예입니다. 메뉴 선택(1~6)에도, 정답 입력(0~선택지 수)에도, 삭제할 번호 선택에도 똑같은 검증 로직이 필요했습니다. 매번 새로 짜는 대신, "어떤 안내문을 보여줄지"와 "허용 범위가 어디부터 어디까지인지"를 매개변수로 받고, 검증을 통과한 정수를 return하는 함수 하나로 통일했습니다.

Part 03

클래스와 객체

왜 함수만으로 안 되고 클래스가 필요했는가.

함수만 쓰면 "이 퀴즈의 정답이 몇 번이었지?"를 알기 위해 매번 여러 변수를 같이 끌고 다녀야 합니다(문제 문자열, 선택지 리스트, 정답 번호, 힌트... 네 개를 따로 관리). 클래스는 이 네 가지를 하나의 덩어리(객체)로 묶어서, "퀴즈 하나"를 quiz라는 이름 하나로 다룰 수 있게 해줍니다.

Quiz 클래스 데이터 + 그 데이터로 하는 일

quiz.py
class Quiz:
    def __init__(self, question, choices, answer, hint=None):
        self.question = question
        self.choices = choices
        self.answer = answer
        self.hint = hint

    def is_correct(self, user_answer):
        return user_answer == self.answer

__init__은 "이 객체가 태어날 때 처음 한 번 실행되는 초기화 함수"입니다. Quiz("CPU란?", [...], 2)처럼 값을 넣어 호출하면 그 값들이 self.question, self.choices 같은 속성(attribute)으로 저장됩니다. self는 "지금 만들어지고 있는 바로 이 객체"를 가리키는 이름표라서, 퀴즈가 6개든 100개든 각자 자기 자신의 문제·선택지·정답을 따로 기억할 수 있습니다. is_correct처럼 속성을 이용해 어떤 동작을 하는 함수를 클래스 안에 두면 메서드(method)라고 부릅니다.

QuizGame 클래스 진행 · 조율 담당

Quiz가 "문제 하나"라면, QuizGame은 "게임 전체"입니다. self.quizzes(리스트), self.best_score, self.history를 속성으로 갖고, play_quiz / add_quiz / list_quizzes / delete_quiz / show_best_score / save_state / load_state를 메서드로 갖습니다. 기능별로 메서드를 나눈 덕분에, 예를 들어 "삭제 기능에 버그가 있다"고 하면 delete_quiz 메서드 하나만 보면 됩니다 — 이것이 "역할별로 메서드를 분리한다"는 요구사항의 실제 의미입니다.

Part 04

파일 입출력과 JSON

프로그램을 껐다 켜도 데이터가 남아있는 이유.

파이썬 변수는 프로그램이 끝나면 메모리에서 사라집니다. 그래서 "다음에 실행할 때도 기억해야 하는 것"은 파일에 적어둬야 합니다. 이 프로젝트는 그 파일로 JSON을 씁니다 — JSON은 {"key": "value"} 형태로 숫자·문자열· 리스트·딕셔너리를 그대로 텍스트로 옮겨 적을 수 있어서, 파이썬의 dict/ list 구조와 거의 1:1로 대응되기 때문입니다.

quiz_game.py — save_state / load_state
def save_state(self):
    data = {"quizzes": [...], "best_score": ..., "history": ...}
    try:
        with open(STATE_FILE, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)
    except OSError as error:
        print(f"⚠️ 데이터 저장 중 오류가 발생했습니다: {error}")

def load_state(self):
    if not os.path.exists(STATE_FILE):
        self.quizzes = list(DEFAULT_QUIZZES)   # 최초 실행 → 기본 데이터
        return
    try:
        with open(STATE_FILE, "r", encoding="utf-8") as f:
            data = json.load(f)
        self.quizzes = [Quiz.from_dict(q) for q in data["quizzes"]]
    except (json.JSONDecodeError, KeyError, TypeError, OSError):
        print("⚠️ 저장된 데이터 파일이 손상되어 기본 퀴즈 데이터로 초기화합니다.")
        self.quizzes = list(DEFAULT_QUIZZES)

try/except가 두 번 등장하는 이유가 다릅니다. 저장할 때는 디스크 오류(OSError) 대비용이고, 불러올 때는 파일이 깨져서 JSON으로 못 읽는 경우(JSONDecodeError)나 구조가 이상한 경우 (KeyError)까지 함께 대비합니다. 둘 다 "예외가 나도 프로그램이 죽지 않고, 기본 퀴즈로 복구해서 계속 실행된다"는 요구사항을 지키기 위한 장치입니다.

state.json이 깨진 상태에서 실행
⚠️ 저장된 데이터 파일이 손상되어 기본 퀴즈 데이터로 초기화합니다.

Git 기초

이 저장소에서 실제로 밟은 절차. "무엇을 했는지"가 아니라 "왜 그 명령이었는지"를 기준으로 정리했습니다.

명령어이 프로젝트에서 한 일왜 필요했나
git init -b main빈 폴더를 저장소로 전환변경 이력을 추적하려면 먼저 git의 관리 대상이 되어야 함
git add수정한 파일을 커밋 후보(스테이징)로 등록한 번에 여러 파일을 고쳐도, 커밋에는 의미 단위로만 묶어 넣기 위함
git commit18개의 기능 단위 스냅샷 기록"언제 무엇이 왜 바뀌었는지"를 나중에 되짚을 수 있게 함
git push로컬 커밋을 GitHub 원격 저장소로 전송내 컴퓨터가 망가져도 코드가 남고, 남과 공유 가능
git checkout -b feature/quiz-play퀴즈 풀기 기능 전용 브랜치 생성·이동아직 불안정한 기능을 main과 분리해서 안전하게 개발
git merge --no-ff완성된 feature/quiz-play를 main에 병합분리해서 만든 기능을 다시 하나의 흐름으로 합침
git clone같은 저장소를 별도 폴더에 복제"다른 컴퓨터에서 이 프로젝트를 새로 내려받는 상황"을 재현
git pullclone한 쪽에서 만든 커밋을 원래 작업 폴더로 반영원격에 생긴 변경사항을 내 로컬로 가져오는 절차를 실습

Part 06

보너스 기능 — 동작 원리

다섯 가지 모두 구현했고, 서로 연결되어 있습니다.

랜덤 출제 + 문제 수 선택 random

quiz_game.py — play_quiz
total = self._get_int_input(f"몇 문제를 풀까요? (1-{available}): ", 1, available)
quizzes_to_play = random.sample(self.quizzes, total)

random.sample(목록, 개수)는 목록에서 중복 없이 개수만큼을 무작위 순서로 뽑아줍니다. "몇 개를 뽑을지"와 "순서를 섞을지"를 한 줄로 동시에 해결하기 때문에, 문제 수 선택 기능과 랜덤 출제 기능이 사실상 같은 코드에서 나옵니다.

힌트 기능 점수 차감

정답 대신 0을 입력하면 quiz.show_hint()가 힌트를 보여주고, 그 문제에 힌트를 썼다는 사실만 기록합니다(같은 문제에서 여러 번 눌러도 1회로 계산). 최종 점수는 다음 공식으로 계산합니다.

score = max(0, round(정답수 / 전체문제수 × 100) − 힌트사용문제수 × 5)

퀴즈 삭제

메뉴 목록을 그대로 보여준 뒤 번호를 받아 self.quizzes.pop(index - 1)로 제거합니다. 메뉴에 항목이 하나 늘면서 종료가 5번에서 6번으로 밀렸고, 그래서 MENU_MAX도 5에서 6으로 바뀌었습니다.

점수 기록 히스토리

퀴즈를 풀 때마다 {"timestamp", "total", "correct", "score", "hints_used"} 한 줄이 self.history 리스트에 쌓입니다. "점수 확인" 화면에서는 전체를 다 보여주지 않고 self.history[-5:]로 최근 5개만, reversed()로 최신순으로 보여줍니다.

Part 07

설명 리허설

미션의 "과제 목표" 문구를 그대로 질문으로 바꿨습니다. 소리 내어 대답해보세요.

Q. 변수가 무엇이고 왜 쓰나요?

이름이 붙은 저장 공간입니다. self.best_score처럼 실행 중에 값이 바뀌는 것들을 담아두려면 변수가 있어야 합니다 — 값이 절대 안 바뀐다면 애초에 변수가 필요 없었을 겁니다.

Q. for와 while은 언제 각각 쓰나요?

몇 번 반복할지 이미 알고 있으면 for(출제할 문제 6개를 순서대로), 몇 번 걸릴지 모르고 "조건이 만족될 때까지" 반복하면 while(올바른 숫자가 입력될 때까지).

Q. __init__과 self의 역할은?

__init__은 객체가 생성되는 순간 실행되는 초기화 메서드이고, self는 지금 만들어지는 그 객체 자신을 가리킵니다. 그래서 Quiz 6개를 만들어도 각자 자기 문제/정답을 따로 갖습니다.

Q. JSON을 왜 데이터 저장에 쓰나요?

파이썬의 리스트·딕셔너리 구조를 거의 그대로 텍스트로 적고, 다시 그대로 읽어올 수 있기 때문입니다. json.dump로 쓰고 json.load로 읽으면 끝이라 변환 코드를 따로 짤 필요가 없습니다.

Q. clone과 pull의 차이는?

clone은 저장소가 로컬에 아예 없을 때 "처음 통째로 내려받는" 것이고, pull은 이미 있는 로컬 저장소에 "원격에 새로 생긴 커밋만 가져와 반영"하는 것입니다. 이 프로젝트에서는 별도 폴더에 clone한 뒤 그곳에서 커밋·push하고, 원래 폴더에서 pull로 그 변경을 받아왔습니다.

Q. 브랜치를 만들고 병합한다는 게 실제로 뭘 한 건가요?

main을 안전하게 두고 feature/quiz-play라는 별도 작업 공간에서 퀴즈 풀기 기능을 완성한 뒤, git merge로 그 결과를 다시 main에 합쳤습니다. 개발 중인 코드가 안정된 코드와 섞이지 않게 하는 것이 목적입니다.
